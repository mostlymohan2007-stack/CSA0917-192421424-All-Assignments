Unsafe query template : SELECT role FROM app_user WHERE username = '<user>' AND password_hash = SHA2('<pass>', 256)
Safe query template   : SELECT role FROM app_user WHERE username = ? AND password_hash = SHA2(?, 256)

Text actually sent to MySQL by the UNSAFE version for L4:
   SELECT role FROM app_user WHERE username = 'admin' -- ' AND password_hash = SHA2('anything', 256)
   (everything after -- is a comment, so the password is never checked)
Text sent for L6:
   SELECT role FROM app_user WHERE username = 'x' UNION SELECT 'ADMIN' -- ' AND password_hash = ...

app_user still has 2 rows after all tests (the stacked DROP TABLE in L7 did not run: the driver rejects multiple statements by default; this protection is not a defence against L4-L6).
